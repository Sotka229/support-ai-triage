# Triage Gateway — автоматизация обработки тикетов поддержки

Система между каналами поддержки (чат, email, веб-форма, мобильное приложение) и helpdesk-ядром.
Она снимает PII, определяет тему и риск обращения, маршрутизирует его, а для безопасных
категорий готовит ответ с опорой на базу знаний — и отправляет его без оператора только тогда,
когда одновременно выполнены все пороги версионируемой политики. Всё остальное уходит человеку.

Репозиторий — конкурсное задание: целевая архитектура в документации плюс минимальный
работающий PoC, который эту архитектуру подтверждает. Это не production-код.

## Быстрый старт

Нужен только Python 3.11 (проверено на 3.11.9; ожидаемо работает на 3.10+).
Внешних зависимостей у PoC нет — pytest нужен только для тестов.

```bash
python demo.py
```

```bash
python -m pytest
```

```bash
python tools/effect_model.py
```

Первая команда прогоняет четыре сценария end-to-end и печатает трассу решений.
Вторая — 190 тестов (~2 секунды; один помечен `xfail` — это задокументированный
дефект валидатора, см. ниже). Третья — пересчитывает таблицы эффекта из
[docs/product.md](docs/product.md): числа в документации порождаются кодом, а не текстом.

Демо можно прогнать не на моке, а на настоящей локальной модели — если установлена
[Ollama](https://ollama.com):

```bash
python demo.py --llm ollama:llama3.1:8b
```

Прогон на живой модели нужен не для красоты: мок цитирует базу знаний дословно, поэтому на нём
нельзя проверить, удержат ли валидаторы систему, когда текст порождает модель. Он вскрыл три
дефекта, которых на моке не видно, — они описаны в [SELF_REVIEW.md](SELF_REVIEW.md).

В контейнере — образ прогоняет тесты на этапе build, поэтому неудачная сборка означает
падение тестов, а не проблему окружения. Проверено: сборка 1 мин, образ 210 МБ,
демо в контейнере даёт тот же результат, что и локально.

```bash
docker build -t support-ai-triage . && docker run --rm support-ai-triage
```

## Какой сценарий демонстрируется

| # | Сценарий | Что показывает |
|---|---|---|
| 1 | Чат: «забыл пароль, письмо не приходит» | happy path: тема определена, статья найдена, черновик обоснован, тикет закрыт автоматически |
| 2 | Email: «с карты списали деньги, это не я» | risky path: PII снят, правило дало CRITICAL, LLM не вызывался вообще, тикет ушёл в FRAUD_TEAM |
| 3 | Мобильное приложение: краш (LLM API лежит) | fallback path: circuit breaker открылся, черновика нет, тикет маршрутизирован, ничего не потеряно |
| 4 | Шесть однотипных жалоб «сайт не открывается» | инцидент: кластер распознан, вместо шести генераций один broadcast |

В конце демо проверяется целостность аудит-лога и отсутствие PII в нём.

## Что реально реализовано, а что архитектурный дизайн

| Компонент | В PoC | В целевой архитектуре |
|---|---|---|
| Нормализация 4 каналов | реальный код: HTML, подписи, цитаты, метаданные | то же + валидация схем и дедупликация доставки |
| PII-редакция | реальный код: 10 классов, номер карты проверяется алгоритмом Луна | правила + NER-модель, DLP на исходящих письмах |
| Правила и красные флаги | реальный код | то же, вынесено в версионируемый конфиг |
| Классификатор темы | TF-IDF char n-grams + центроид, 39 обучающих примеров — baseline | эмбеддинги (rubert-tiny2 / multilingual-e5-small, ONNX int8) + LogReg с калибровкой |
| Поиск по базе знаний | TF-IDF по словам, 8 статей | BM25 (OpenSearch) + dense (pgvector/Qdrant) + RRF + cross-encoder |
| Генерация черновика | мок по умолчанию; опционально настоящая локальная LLM через Ollama (`--llm ollama`) | каскад self-hosted Qwen3-8B (vLLM) -> внешний frontier-API |
| Валидаторы безопасности | реальный код: groundedness, PII, prompt injection, обещания денег | + NLI-проверка цитат, safety-suite в CI |
| Политика решения | реальный код: пороги, allowlist, hard-deny | то же + A/B по версиям политики |
| Аудит | JSONL с цепочкой хешей | append-only в PostgreSQL + выгрузка в S3 с WORM |
| Очередь между путями | обычный вызов функции | Kafka, отдельные деплойменты быстрого и медленного пути |

Подробное сопоставление — в [docs/architecture.md](docs/architecture.md), §8.

## Допущения и ограничения

- Пороги политики (0.90 уверенность, 0.75 groundedness) заданы экспертно и требуют калибровки
  на реальных данных. Порог сходства с базой знаний в PoC равен 0.35, а не 0.55 как в целевой
  архитектуре: у TF-IDF другое распределение косинусов, и порог отсечения — свойство ретривера.
- Уверенность классификатора не калибрована и на чистых примерах вырождается в 1.0. Это
  известное свойство softmax по косинусам, а не признак качества модели.
- Валидатор groundedness измеряет пересечение словоформ с источником, а не следование из него.
  На прогоне живой модели это дало измеренный дефект: правдоподобная выдумка, собранная из
  лексики базы знаний, получает 1.000 и проходит порог автозакрытия — причём разрыв тем шире,
  чем больше фрагментов в контексте. Зафиксировано `xfail`-тестом в
  [tests/test_safety_limits.py](tests/test_safety_limits.py), разбор — в
  [SELF_REVIEW.md](SELF_REVIEW.md).
- Обучающая и проверочная выборки лежат в разных файлах (39 и 15 примеров), качество меряется
  на holdout — но 15 примеров не дают статистики, это проверка работоспособности, не оценка.
- Запуск проверен тремя способами: локально, с чистого клона репозитория и в контейнере
  (демон Docker поднимался в WSL — Docker Desktop на машине разработки не стартует).
  Внутри образа прогоняются те же 190 тестов: интеграционный тест с локальной LLM там
  пропускается, потому что Ollama в контейнер не проброшена.
- Все четыре mermaid-диаграммы проверены не на глаз, а прогоном через официальный
  `@mermaid-js/mermaid-cli`: рендерятся без ошибок. Схема компонентов намеренно вертикальная
  (`flowchart TB`) — горизонтальная версия давала полосу 2384×527, нечитаемую в ширине страницы
  GitHub.
- Нет HTTP-слоя, аутентификации, миграций, метрик Prometheus, оператора UI и A/B-инфраструктуры —
  всё это сознательно вынесено в дизайн, см. [WORKLOG.md](WORKLOG.md).

## Зачем это бизнесу

При 200k тикетов в сутки поддержка стоит порядка 12.1 млрд ₽ в год, и линейный рост найма
вместе с трафиком — главный ограничитель. MVP автоматизирует 11.7% потока и ускоряет обработку
ещё 35% за счёт черновиков оператору, что даёт около 1.47 млрд ₽ годового эффекта — 12.1%
бюджета поддержки, а не обещание «отменить поддержку». Ценность не только в деньгах: типовое
обращение получает корректный ответ ночью и во время инцидента, когда оператор физически
недоступен, а рискованные категории гарантированно доходят до человека, потому что запрет на
автоответ реализован правилами, а не надеждой на модель. Стоимость LLM при этом остаётся
пренебрежимой на фоне ручного труда (около 35 млн ₽ в год, 1.03 ₽ за черновик), а расчёт
чувствительности показывает главное: даже при вдвое худшем качестве проект остаётся в плюсе,
поэтому останавливать раскатку нужно по CSAT и доверию, а не по ROI. Полный расчёт и план
пилота — в [docs/product.md](docs/product.md).

```
src/triage/      компоненты PoC: normalizer, pii, rules, classifier, dedup,
                 retrieval, llm, llm_ollama, safety, policy, audit, pipeline
tools/           effect_model.py — расчёт годового эффекта, покрыт тестами
data/            39 обучающих и 15 проверочных тикетов, 8 статей базы знаний, 4 сценария
tests/           190 тестов: по модулю на файл, end-to-end сценарии и измеренные
                 границы валидатора (test_safety_limits.py)
demo.py          демонстрация четырёх путей + проверка аудит-лога
```
